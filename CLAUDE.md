# football-decision

Текстовый прототип футбольной decision-RPG. Язык игры — украинский; язык кода, комментариев,
тестов и README — русский. Обоснования решений живут в комментариях кода и README; `DESIGN.md` —
целевая картина и дорожная карта (M1..M5), правки сверяются с ней, а не с последним логом.

## Правила

- **Никаких процентов и вероятностей на игровых экранах и в текстах эпизодов.** Игрок видит ярлыки
  («упевнено / ризиковано / відчайдушно», «утримати / створити / вирішити») и модификаторы после броска.
  Тест `tests/acceptance.test.ts` это проверяет.
- **После любой правки `src/engine/balance.ts` или `src/content/episodes.json` — `npm run sim -- 2000`.**
  Три проверки должны быть «ок»; цифры в README обновить.
- **Имена игроков в контенте — только плейсхолдеры** (`{partner}`, `{striker.dat}`, `{them.striker}`).
  Формы падежей — в `src/content/roster.json`. Зашитая фамилия валит тест.
- **`past` и `recap` в эпизоде не должны повторять друг друга:** `past` — поступок
  («пробив з льоту»), `recap` — последствие («і м’яч влетів у дев’ятку»). Из них собирается пересказ матча.
- Атрибуты опций — из десяти (`Attribute` в types.ts); каждый атрибут должен использоваться хотя бы
  одной опцией (тест), иначе он мёртвый на карточке.
- Эпизод: 3–4 опции, в каждой все четыре исхода, минимум две разные формы риска,
  `effect: great` — только там, где чистый исход действительно решает эпизод (гол/ассист).
- «Відчайдушно» — редкость: не больше одной такой опции на эпизод и не в каждом эпизоде.
- Форма риска = полоса катастрофы по сырым кубикам (`CATASTROPHE_BAND`), скилл её не выкупает.
  Любая правка, из-за которой сильный атрибут делает риск безопасным, откатывается.
- **Складність** (`EpisodeOption.difficulty`, −3…+4, `balance.ts:DIFFICULTY`) — вторая ось: форма —
  цена ошибки, складність — насколько трудно сделать. Двигает пороги чистого/«але»
  (`tierFor(..., difficulty)`), полосу катастрофы — нет. Обязательна у каждой опции (тест); в эпизоде
  ≥2 разных цели среди безусловных опций; цель ≥ 20 — только у `standard`/`great`. Ориентиры:
  откатити/притримати/промовчати −3…−2, стандартное действие 0, удар здалеку/черпак/п’яткою/паненка
  +2…+4. На кнопке и экране броска — `cleanTarget(position, difficulty)` / `Resolution.target`,
  не `THRESHOLDS[position]` напрямую.
- **Каждый `cost`-исход содержит осязаемый плюс** (кутовий, ключовий пас, єдиноборство, командний гол
  или ≥3 к доверию/трибунам) и конкретную цену. «Ничего не случилось, +1» — это `fail`, а не `cost`.
- Реплики второго голоса после броска — `src/content/flavor.json`: правило = `when` (+ `family`/`phase`
  сцены) + `voice` (ТРИБУНИ/ТРЕНЕР/ТАБЛО/ГОДИННИК/СУДДЯ/ТІЛО/КУРАЖ/ВОРОТАР/ПАРТНЕР/СУПЕРНИК) + `lines`.
  Пул — все подходящие правила с весом 3^ключей, виденные в этом и последних матчах строки уступают
  свежим (`session.flavorSeen`, `history.recentFlavor`); строгое «самое конкретное» давало 34% повторов
  за сезон. У каждой семьи ≥3 строки на каждый исход (тест). Тон — Disco: наблюдение, не оценка; без «!»;
  строка не утверждает событий, которых нет в исходе (гол, замена, вторая жёлтая); плейсхолдеры ростера.
- **Лента между эпизодами — `src/content/feed.json`** (`engine/feed.ts`), правило = `kind` + `when` (как у
  flavor, плюс `venue`/`weather`/`strength`/`flags`) + `lines`; выбор тот же (`pickFresh`: 3^ключей,
  виденные уступают свежим, `session.feedSeen` + `history.recentFeed`). Виды: `filler`, `goalUs`/`goalThem`
  (гол ленты, с манерой, обязателен `{scorer}`), `goalUsEcho`/`goalThemEcho` (гол из исхода эпизода —
  только автор и счёт, манеру описал исход, спорить с ним нельзя), `halftime` (`{score}`), `knock`,
  `kickoff`. У каждого вида есть безусловное правило; флаги в `when` — только `them_*` и системные.
  Строки-константы в `match.ts` не возвращать: 12 строк давали 38% повторов внутри матча.
- **Стрічка між матчами — `src/content/posts.json`** (`engine/posts.ts`, экран `PostsScreen` после таблицы):
  пародия на твиттер, `accounts` + `posts` `{ group, account, when, lines, reply? }`. Группы и квота
  (`postQuota(season)`: первый сезон — про нас 3, общих 7; со второго — `POST_QUOTA`): `self` 3 (болельщики о персонаже — по факту матча: гол, оценка, доверие, флаги,
  доминирующий голос карьеры), `league` 2 (таблица, следующий соперник по `them_*`), `world` 2
  (большой футбол — **реальные клубы можно, реальные люди — только под искажёнными, но узнаваемыми
  именами**: Риштиану Коналду, Рабріціо Фомано, Джанні Ніфантіно, Пеп Гвардеола — решение 19.09;
  тест держит список настоящих написаний и валит их;
  Россия — аккаунт `rufootball`, жёстко, но про институции), `cross` 1 (пересечение миров),
  `meta` 1 (FM, Disco Elysium, EA). Выбор — `pickFresh`, память `history.recentPosts`; `when.week: [ids]` — дела прошлой недели
  (`career.weekLog`), так стрічка отвечает на побачення/подкаст/план тренера. Клубы таблицы и
  последний соперник — через `extra` (`{leader}`, `{bottom}`, `{last}` + `.gen`); у клубов только
  nom/gen — после «з/із/у» ставить «проти „{x.gen}“», не «з „{x}“». Пост не утверждает событий,
  которых не было (вторая жёлтая — нет; «суддя пояснив, що друга буде» — да). У каждой группы —
  безусловные правила, иначе к 8-му туру пул сохнет (тест «за сезон без повторов»).
  **Тон фанатов — как пишут**: с маленькой, без тире, «шо», КАПС после поражения, ))); издания и
  пародии — чисто. Виды: `kind: poll` (+`poll: []`), `deleted` (оригинал — в `reply` через `{quote}`),
  `promo`, `live` (+`live: [от, до]`). **Ответ игрока** — `replyOptions: [{ text, reaction, effect }]`,
  `effect` как у дела недели; один на стрічку, подмешивается с `REPLY_CHANCE`; применяется через
  `applyWeek`, который дополняет `career.nextMatch`, не затирает (тест в posts.test.ts). Экран
  `LevelUpScreen` — только при `BALANCE.growth.levels` или `unspentPoints > 0`. **Момент матча**:
  `when.moment: worst|best` + `{moment.minute}`/`{moment.ord}`/`{moment.acc}`/`{moment.past}`/`{moment.recap}`
  (`pickMoments` в match.ts → `OurResult.moments`); ключи плейсхолдеров — только строчные латинские
  (`fillNames` иначе их не видит); один пост о моменте на стрічку гарантирован.
- У каждого варианта есть `voice` (кто и что говорит), голос слышно только сильный — см. `voices.ts`.
- **Голос бачить** (`EpisodeOption.insight`, Disco Elysium: пассивная проверка). Сильный атрибут
  (`BALANCE.insightMinMod`, `voices.ts:voiceSees`, только атрибутные голоса) замечает деталь, которой
  нет в сетапе, — строка над вариантами — и только из-за неё появляется вариант; слабый игрок его не
  видит и не знает, что он был. `insight.line` — факт, не совет, без «!»; `voice.who` тот же;
  атрибут броска — чувство этого голоса. Вариант со вставкой — сверх 3–4 безусловных (не больше одного
  условного на эпизод), бонусов к броску не даёт; **его выигрыш — складність ≤ −2 при той же форме**:
  знание делает действие проще, не безопаснее (тест: цель ниже соседей той же формы и масштаба). `availableOptions` без
  `player` такие варианты прячет. Стартовый Реєс видит Бачення и Інстинкт, не Тіло/Холоднокровність.
  **Его и Команда бачать по состоянию матча** (`voiceSeesNow`): Его — на своей серии или кураже ≥
  `egoSeesMomentum`, Команда — на серии или доверии ≥ `teamSeesTrust`; так дело недели «Его гучніше»
  (стартовая серия) открывает вставку Его в первом эпизоде. На кнопке — чип «відкрив <голос>», после
  броска — строка «<голос> побачив цей варіант»: игрок должен связать кнопку с голосом, не с удачей.
- **Флаги недели в сценах** (`week_set_pieces`, `week_tactics`, `week_promise`): дело ставит флаг с
  правилом в `flags.json`, а в эпизоде есть вариант с `requires.flags` (чип «з тижня») и сетап с
  `when.flags`, который прямо ссылается на тиждень («у вівторок ви прогнали його сорок разів»).
  Вариант обязан снять флаг во всех исходах. Тест «правило никто не ставит» считает и дела недели.
- Рост персонажа (M2) — только через `career.ts`: `effectivePlayer()` для матча,
  `applyMatchToCareer()` в конце, `consumeStartPenalty()` в начале следующего. Не трогать
  `PLAYER.attrs` напрямую и не завести второй источник правды для «текущих атрибутов».
  **Очко = +1 к модификатору** (`POINT_VALUE` = `ATTR_MOD.step`), не +1 к значению.
  **Уровни выключены** (`BALANCE.growth.levels = false`, решение 17.09): опыт и уровень считаются,
  очков не дают; рост — только тренировки недели (`trainToPoint` = 3). Код уровней и `LevelUpScreen`
  оставлены, включаются одним полем; миграция карьеры фантомных очков при выключенных уровнях не даёт.
- **Тиждень між матчами** — `engine/week.ts` + `content/activities.json` (66 дел), экран `WeekScreen`
  тонкий. **v3 (19.09):** `BALANCE.week.days` × `perDay` предложений (`offerWeekDays`: голоса в дне
  разные, ≤ `maxPerVoice` на неделю, при нехватке голосов лимит снимается — закрытый город), одно дело
  в день, у дела `outcomes` (1–3, `ActivityOutcome`): вес × `outcomeVoiceBoost` если `voice` —
  доминантный голос карьеры (`dominantCareerVoice`, ≥ `dominantMin`) × `outcomeCheckPass/Fail` по
  `check {attr, min}` (модификатор) × `outcomeSituationBoost` если `boost` (условие `ActivityWhen`)
  совпал. Исходы считаются в `planWeek` тем же rng, что предложения (перезагрузка не перебрасывает);
  применяется эффект исхода вместо `effect` дела (`withOutcome`). `followUp` — id сцены из
  `content/weekscenes.json` (`WeekScene`: setup + 3–4 варианта, ровно один с `insight {who, line}`,
  показывается только если `weekVoiceSees(who)`: атрибутные — `voiceSees`, Его — трибуны ≥ 7 или
  доминантный, Команда — доверие ≥ `teamSeesTrust`); одна сцена на неделю. `neglectPenalties`:
  голос, предлагавший `neglectWeeks` недель подряд без выбора, — `quieter` на матч
  (`career.voiceNeglect`). Всё закрывает `finishWeek` (isходы + сцена + обида → `applyWeek` →
  `recordWeek` с `outcomes`/`scene`). **Правила исходов:** текст — 1–3 предложения с иронией, `note`
  обязателен, эффект обязан оставить след (тест `week3`), ⅔ дел — с развилкой, ни один исход не
  «просто хорошо/плохо» без цены или плюса; `train: "choice"` сохраняется в исходе, иначе выбор
  атрибута на карточке пропадёт. Между днями — мировой пост (`buildPosts` в App, квота `world`).
  `offerWeek` (шесть по голосу) остался для тестов и старых прогонов.
  Старое (v2) ниже остаётся в силе. Дело = «какой голос беру на матч»:
  `louder`/`quieter` — ±1 к модификатору атрибутов голоса на один матч (`career.nextMatch.attrBonus`
  → `effectivePlayer(..., matchBonus)`), `stamina`/`composure`/`fanHype`/`momentum` — старт
  (`Carryover.startDelta`), `coachTrust` — сразу, `train` — счётчик, `trainToPoint` = +1 очко навсегда,
  `flags` с `after` — отложенные (`CarriedFlag.after`, `Mark.whenText`), `heal`. `note` — строка
  брифинга, обязательна. Его/Команда атрибутов не имеют: `louder` — матч начинается с их серии
  (`Carryover.voiceStreak`), `quieter` — голос замовк на `week.muteEpisodes` эпизодов (`voices.muted`).
  Закрытый город оставляет ситуационные дела по `when.flags`. Флаг из матча и отложенный с тем же id
  не дублируются (`applyMatchToCareer`, `createMatch`). Дело Его с «Его гучніше» в `note` обязано иметь
  `louder: ["ego"]` — иначе вставки Его не откроются, а бирка соврёт. После разгрома или при низком доверии `coachLocksCity` — только Тіло/Бачення/
  Холоднокровність. **Ирония в `line` — фишка игры**: одна строка, наблюдение, без «!»; дело без
  строки-наблюдения в пул не попадает. Ситуационные дела (травма, флаг партнёра, низ таблицы) —
  `weight` 8, чтобы всплывали. Балансировать `npm run sim -- --weeks 150`: разрыв политик недели ≤ 15%.
- **Тема и экран матча (19.09, макеты А2/Г):** токены в `styles.css :root` (`--font-text` Lora,
  `--font-mono` IBM Plex Mono, `--font-caps` Oswald, `--v-<voice>` цвета голосов); шрифты локально
  в `public/fonts` + `public/fonts.css` — не подключать Google Fonts по сети (APK офлайн). Матч:
  `MatchScreen` (поле `Pitch`, стрічка-диалог, зона «на кубик» из `stateMods`), `EpisodeCard` (голоса
  до вариантов, варианты `N. - [форма ціль] ярлык`; на кнопке нет атрибута/бонуса/цены — решение
  пользователя), `RollView` (кубики-барабан с раздельной остановкой → сумма → чипы факторов и тикающий итог →
  формула → вердикт-штамп → исход; без баннера/таблицы/зоны «на кубик» — решение 19.09). Новый модификатор в `context.ts` — сразу ветка в `ui/icons.tsx: modIcon`, иначе
  точка. Поле: точка гравця по `family`/`phase` (`Pitch.tsx: FAMILY_SPOT`); новая семья — координата
  там же; когда появится Phaser, заменить на `zone` эпизода. Остальные экраны — старая структура в
  новой палитре, переводить по одному.
- Карточка игрока (`ui/PlayerCard.tsx`) — удостоверение: шапка с полями, девиз доминирующего
  голоса карьеры, **голоси первыми** (бачить / чутно / мовчить, Его и Команда — по тому, кого
  слушали), потом сезон, кар’єра, атрибуты по группам. Тексты голосов — в `VOICES` там же.
- **Исход называет конкретного партнёра/соперника (assist/teamGoal/concede) — обязан иметь
  `apply.scorer`**, ключ ростера, названный в тексте. Без него лента матча объявит гол случайным
  именем — тест `tests/content.test.ts` это ловит. Крит-исход (`outcomes.crit`) всегда выбирается
  через `resolve.ts:pickOutcome()`, никогда не дублировать эту проверку локально в UI.
- Реальных футболистов и тренеров по имени в контенте нет — только generic-описание техники (право
  на публичность); реальные **клубы** — только в стрічці (`posts.json`, группы `world`/`cross`), решение
  18.09. Исключение — уже устоявшиеся общие термины футбола («паненка»).
- Голос, который слушают дважды подряд (`state.voices.streak`), становится громче — не добавлять
  третий такой эффект без причины, у голосов уже есть счётчик и серия, использовать их.
- Флаги-последствия — `src/content/flags.json`; реактивные эпизоды — `rx_*` с `requires.flags`,
  в тексте допустимы `{trigger.past}` и `{trigger.minute}`; их исходы обязаны снимать свой флаг.
  Успех на риске не должен давать только минус (флаг с двумя правилами — минус и плюс).
- Условия матча (`conditions.ts`) игрок не выбирает; `neutralConditions()` — для тестов и прогона,
  нейтральные условия не добавляют ни одной строки модификатора (есть тест). Новый соперник —
  запись в `roster.json` → `opponents` с падежами и `strength`.
- **Новый эпизод — сразу с 2–3 сетапами и весом:** новые оборонительные — `weight` 0.5–0.6 (в открытых
  слотах они разбавляют атаку, критерий «матчей с голом ≥ 20%» уезжает), новые атакующие — 1.2–1.4; самая
  физическая опция — 9–12 сил (критерий по стамине). После добавления — `sim 2000` и `--season 12`.
- **Установка тренера в сценах:** `when.instruction` (hold/press/free) у сетапов и `requires.instruction` у
  эпизода — «автобус», гегенпресинг, володіння читаются словами, не строкой брифинга. **Маркерные флаги**
  (`plan_bus`/`plan_press`/`plan_possession`, `viral_story`, `podcast_talk`, `flashy_week` + конкретные
  `dubai_photos`…): правило в `flags.json` с `value: 0` — только для сетапов и реактивных сцен,
  `context.ts` их пропускает. Дело недели может быть сеттером флага для `rx_` (тест это учитывает):
  побачення → `viral_story` → `rx_insta_taunt`; реактивная сцена обязана снять свой флаг.
- **Квота атаки выключена** (`BALANCE.match.minAttack` = 0, решение 19.09): форму матча задаёт пул под
  персонажа (АПЗ — атакующие сцены), а не планировщик. «Матчей с голом» в `sim`/`acceptance` считается по
  случайной политике — не суммарно с `always_safe`, который никогда не бьёт. Если доля голов проседает
  при расширении пула — писать атакующие сцены, не квоту.
- **Организационные эпизоды** (владение, темп, скан, хибний рух) вознаграждаются не голом: тренер +6…+8,
  трибуны ±0, `keyPass`/`duelWon`, `partner_trusts`, и `followUp` в существующий удар (`fin_shot`,
  `ep_edge_of_box`, `ep_between_lines`, `ep_progressive_pass`) с `followUpElse`. `effect: great` у них
  не ставить — момент решает цепочка.
- Свежесть реплик и ленты — двухступенчатая: `pickFresh(pool, seen, rng, seenNow)`; `seen` — сезон,
  `seenNow` — этот матч (`session.flavorSeenNow` / `feedSeenNow`). Не сводить к одному множеству: к
  12-му туру сезонная память съедает весь пул ленты, и повтор внутри матча возвращается.
- **Новая ситуация — сначала вариант сетапа, потом эпизод.** `Episode.setups[]` — `{ when, text }` с
  условием как у `flavor.json` (+ `venue`/`weather`/`strength`/`flags`), побеждает самое конкретное;
  опции и исходы не меняются. Новый эпизод — только если решение другое, а не сцена. После правки
  пула — `npm run sim -- --season 12`, цифры повторов в README обновить.
- `requires.score` — эпизод только при таком счёте; ставить `minMinute ≥ 45` (тест), иначе он зависает
  в плане. Проверяется при показе, как `notFlags`; подменить нечем — берётся свежий эпизод вне плана.
- Память между матчами — `BALANCE.match.memory`, кривая, а не список; `episodeMemory()` в истории
  отдаёт `id → возраст`. Не возвращать плоский `recentWeight`: он даёт 42% повторов к 4-му матчу.
- **Соперники — без фамилий.** `roster.json → opponents.*.players` — характеристики с падежами, только
  мужские и с `gen` = винительный («їхній ветеран», не «зірка», не «роботяга», не «фантазиста»);
  `trait` обязателен у striker/winger/mid и даёт флаг `them_<trait>` на матч с правилом в `flags.json`.
  **Черты на бросок не складываются** (`context.ts`): идёт одна, самая сильная — у «Сан-Дореа» три черты
  били по позиції в обороне на −3 (лог тестера 18.09). Остальные флаги применяются все.
  У каждой роли ≥2 `variants` (нейтральная позиция — «опорник», «хавбек», «латераль», — и образ —
  «здоровань», «лисий стоппер»); `rosterFor(key, rng)` выбирает одно имя на матч. Роль `cb` —
  защитник-антагонист для сетапов (`{them.cb}`), без характеристики. Своих — наоборот, по имени: `self`, `sub`,
  `coach`, `rb`/`lb`/`cb2`/`winger` — использовать в новом контенте, а не «дублер»/«тренер»/«захисник».
- Персонаж в ленте и протоколе — `{self}`/`apply.scorer: "self"` для своего гола; не возвращать
  безымянное «Гол!».
- Голоса имеют вес (`BALANCE.voice`, `context.ts`): голос атрибута +1, серия Его/Команди −1 на
  «другой стороне». Его и Команда к броску бонуса не дают — не добавлять.
- Сезон — `engine/season.ts`: расписание, чужие результаты, таблица, вердикт; UI только читает.
  Соперник и поле матча берутся из `ourFixture()`, не из случайности `generateConditions`.
- **Цепочки.** `apply.followUp: "<id>"` — исход ведёт в следующее решение в том же слоте; рядом
  обязателен `apply.followUpElse` (что происходит, если цепочка не сработала — лимит или звено уже
  было). Звенья — `followUpOnly: true` (`fin_*`): не планируются, не всплывают, в тексте допустим
  `{trigger.past}`. Не вести цепочку из исхода, чей текст уже решил эпизод (гол) — только из «ти
  виходиш на удар / штрафний / пенальті».
- Манера удара — опция модуля `fin_shot`/`fin_penalty`, не новый эпизод. Свойство воротаря —
  `keeper.trait` в ростере + правило с `options: [...]` в `flags.json` (по id опции, не по атрибуту).
  Читаемость — через `keeper_read`; в сетапах `when.flags: ["keeper_read", "keeper_<trait>"]`.
  Условные опции — `requires.flags`; безусловных у эпизода всё равно 3–4 (тест).
- У каждого эпизода `family`; новый эпизод без семьи валит тест. Семьи давят память слабее id.
- Баланс сезона мерить не только `sim`, но и W/D/L по силе соперника (скрипт в README, раздел
  «Пересборка баланса»): цель — наугад против равных ≈ 40/20/40, против слабых ≈ 70/15/15.
  Матчей с голом игрока — не ниже 20% (критерий); свои голы ленты — не поднимать выше 0.03.
- `knock` (мікротравма) — системный флаг ленты и исходов, снимается только через `rx_knock`;
  не превращать в автоматический штраф без решения. Травм (`injured`) — не больше
  `BALANCE.injury.maxPerSeason` за сезон: дальше исход даёт `knock` (`applyChoice`, `career.injuriesSeason`).
- Доверие тренера между матчами регрессирует к старту с силой `BALANCE.coachTrustReversion` (0.25,
  было 0.4): цена «тренер −8» за дело недели должна доживать до следующего тура, а лояльность —
  дела недели с `coachTrust: +`. Вердикт сезона: лава при низе таблицы, доверии < 45 или средней
  оценке < 5.2 — любого одного достаточно (`seasonVerdict`); при случайной игре ~30% сезонов.
- Флаги про людей (`CARRIED_FLAGS` в career.ts) переживают свисток; в текстах реактивных эпизодов —
  `{trigger.when}` / `{trigger.When}`, а не «на {trigger.minute}-й»: для перенесённого флага это
  «ще минулого матчу». Каждый флаг из контента — либо правило в `flags.json`, либо системный
  (`booked`/`injured`/`sent_off`/`tired`); правило без эпизода, который его ставит, валит тест.

```
npm run dev      # localhost:5179 (см. .claude/launch.json)

npm run sim -- --weeks 150   # политики недели між матчами на дистанции сезона
npm run qa -- 300            # QA-прогон карьер: инварианты (флаги, атрибуты, неделя, уровень), исключения
npm run build    # dist/ — деплоится на GitHub Pages workflow'ом
```
