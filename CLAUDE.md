# football-decision

Текстовый прототип футбольной decision-RPG. Язык игры — украинский; язык кода, комментариев,
тестов и README — русский. Обоснования решений живут в комментариях кода и README; `DESIGN.md` —
целевая картина и дорожная карта (M1..M5), правки сверяются с ней, а не с последним логом.

## Правила

- **Никаких процентов и вероятностей на игровых экранах и в текстах эпизодов.** Игрок видит ярлыки
  («упевнено / ризиковано / відчайдушно», «утримати / створити / вирішити») и модификаторы после броска.
  Тест `tests/acceptance.test.ts` это проверяет.
- **После любой правки `src/engine/balance.ts` или `src/content/episodes.json` — `npm run sim -- 2000`.**
  Три проверки должны быть «ок»; цифры в README обновить.
- **Имена игроков в контенте — только плейсхолдеры** (`{partner}`, `{striker.dat}`, `{them.striker}`).
  Формы падежей — в `src/content/roster.json`. Зашитая фамилия валит тест.
- **`past` и `recap` в эпизоде не должны повторять друг друга:** `past` — поступок
  («пробив з льоту»), `recap` — последствие («і м’яч влетів у дев’ятку»). Из них собирается пересказ матча.
- Атрибуты опций — из десяти (`Attribute` в types.ts); каждый атрибут должен использоваться хотя бы
  одной опцией (тест), иначе он мёртвый на карточке.
- Эпизод: 3–4 опции, в каждой все четыре исхода, минимум две разные формы риска,
  `effect: great` — только там, где чистый исход действительно решает эпизод (гол/ассист).
- «Відчайдушно» — редкость: не больше одной такой опции на эпизод и не в каждом эпизоде.
- Форма риска = полоса катастрофы по сырым кубикам (`CATASTROPHE_BAND`), скилл её не выкупает.
  Любая правка, из-за которой сильный атрибут делает риск безопасным, откатывается.
- **Каждый `cost`-исход содержит осязаемый плюс** (кутовий, ключовий пас, єдиноборство, командний гол
  или ≥3 к доверию/трибунам) и конкретную цену. «Ничего не случилось, +1» — это `fail`, а не `cost`.
- Реплики по ситуации — в `src/content/flavor.json`; побеждает самое конкретное правило.
- У каждого варианта есть `voice` (кто и что говорит), голос слышно только сильный — см. `voices.ts`.
- Рост персонажа (M2) — только через `career.ts`: `effectivePlayer()` для матча,
  `applyMatchToCareer()` в конце, `consumeStartPenalty()` в начале следующего. Не трогать
  `PLAYER.attrs` напрямую и не завести второй источник правды для «текущих атрибутов».
- **Исход называет конкретного партнёра/соперника (assist/teamGoal/concede) — обязан иметь
  `apply.scorer`**, ключ ростера, названный в тексте. Без него лента матча объявит гол случайным
  именем — тест `tests/content.test.ts` это ловит. Крит-исход (`outcomes.crit`) всегда выбирается
  через `resolve.ts:pickOutcome()`, никогда не дублировать эту проверку локально в UI.
- Реальных футболистов, клубов и их фирменных приёмов по имени в контенте нет — только generic-описание
  техники (право на публичность). Исключение — уже устоявшиеся общие термины футбола («паненка»).
- Голос, который слушают дважды подряд (`state.voices.streak`), становится громче — не добавлять
  третий такой эффект без причины, у голосов уже есть счётчик и серия, использовать их.
- Флаги-последствия — `src/content/flags.json`; реактивные эпизоды — `rx_*` с `requires.flags`,
  в тексте допустимы `{trigger.past}` и `{trigger.minute}`; их исходы обязаны снимать свой флаг.
  Успех на риске не должен давать только минус (флаг с двумя правилами — минус и плюс).
- Условия матча (`conditions.ts`) игрок не выбирает; `neutralConditions()` — для тестов и прогона,
  нейтральные условия не добавляют ни одной строки модификатора (есть тест). Новый соперник —
  запись в `roster.json` → `opponents` с падежами и `strength`.
- **Новая ситуация — сначала вариант сетапа, потом эпизод.** `Episode.setups[]` — `{ when, text }` с
  условием как у `flavor.json` (+ `venue`/`weather`/`strength`/`flags`), побеждает самое конкретное;
  опции и исходы не меняются. Новый эпизод — только если решение другое, а не сцена. После правки
  пула — `npm run sim -- --season 12`, цифры повторов в README обновить.
- `requires.score` — эпизод только при таком счёте; ставить `minMinute ≥ 45` (тест), иначе он зависает
  в плане. Проверяется при показе, как `notFlags`; подменить нечем — берётся свежий эпизод вне плана.
- Память между матчами — `BALANCE.match.memory`, кривая, а не список; `episodeMemory()` в истории
  отдаёт `id → возраст`. Не возвращать плоский `recentWeight`: он даёт 42% повторов к 4-му матчу.
- **Соперники — без фамилий.** `roster.json → opponents.*.players` — характеристики с падежами, только
  мужские и с `gen` = винительный («їхній ветеран», не «зірка», не «роботяга», не «фантазиста»);
  `trait` обязателен у striker/winger/mid и даёт флаг `them_<trait>` на матч с правилом в `flags.json`.
  У каждой роли ≥2 `variants` (нейтральная позиция — «опорник», «хавбек», «латераль», — и образ —
  «здоровань», «лисий стоппер»); `rosterFor(key, rng)` выбирает одно имя на матч. Роль `cb` —
  защитник-антагонист для сетапов (`{them.cb}`), без характеристики. Своих — наоборот, по имени: `self`, `sub`,
  `coach`, `rb`/`lb`/`cb2`/`winger` — использовать в новом контенте, а не «дублер»/«тренер»/«захисник».
- Персонаж в ленте и протоколе — `{self}`/`apply.scorer: "self"` для своего гола; не возвращать
  безымянное «Гол!».
- Голоса имеют вес (`BALANCE.voice`, `context.ts`): голос атрибута +1, серия Его/Команди −1 на
  «другой стороне». Его и Команда к броску бонуса не дают — не добавлять.
- Сезон — `engine/season.ts`: расписание, чужие результаты, таблица, вердикт; UI только читает.
  Соперник и поле матча берутся из `ourFixture()`, не из случайности `generateConditions`.
- **Цепочки.** `apply.followUp: "<id>"` — исход ведёт в следующее решение в том же слоте; рядом
  обязателен `apply.followUpElse` (что происходит, если цепочка не сработала — лимит или звено уже
  было). Звенья — `followUpOnly: true` (`fin_*`): не планируются, не всплывают, в тексте допустим
  `{trigger.past}`. Не вести цепочку из исхода, чей текст уже решил эпизод (гол) — только из «ти
  виходиш на удар / штрафний / пенальті».
- Манера удара — опция модуля `fin_shot`/`fin_penalty`, не новый эпизод. Свойство воротаря —
  `keeper.trait` в ростере + правило с `options: [...]` в `flags.json` (по id опции, не по атрибуту).
  Читаемость — через `keeper_read`; в сетапах `when.flags: ["keeper_read", "keeper_<trait>"]`.
  Условные опции — `requires.flags`; безусловных у эпизода всё равно 3–4 (тест).
- У каждого эпизода `family`; новый эпизод без семьи валит тест. Семьи давят память слабее id.
- Баланс сезона мерить не только `sim`, но и W/D/L по силе соперника (скрипт в README, раздел
  «Пересборка баланса»): цель — наугад против равных ≈ 40/20/40, против слабых ≈ 70/15/15.
  Матчей с голом игрока — не ниже 20% (критерий); свои голы ленты — не поднимать выше 0.03.
- `knock` (мікротравма) — системный флаг ленты и исходов, снимается только через `rx_knock`;
  не превращать в автоматический штраф без решения.
- Флаги про людей (`CARRIED_FLAGS` в career.ts) переживают свисток; в текстах реактивных эпизодов —
  `{trigger.when}` / `{trigger.When}`, а не «на {trigger.minute}-й»: для перенесённого флага это
  «ще минулого матчу». Каждый флаг из контента — либо правило в `flags.json`, либо системный
  (`booked`/`injured`/`sent_off`/`tired`); правило без эпизода, который его ставит, валит тест.
- **Тиждень між матчами** — `engine/week.ts` + `content/weeks.json`, экран `WeekScreen` тонкий (под
  замену новым UI, логика только в движке). Сцена — 2–3 варианта без броска, эффект через
  `apply`: `coachTrust` сразу, `stamina`/`fanHype`/`composure`/`note` — на старт следующего матча
  (`career.nextStart` → `Carryover.startDelta`), флаги — `{ flag, after, past }` в `carriedFlags`:
  `after` — сколько матчей флаг едет молча, `past` — поступок для `{trigger.past}`, «когда» пишет
  `whenTextFor()` в `Mark.whenText`. Флаг недели обязан иметь реактивный эпизод (тест). В тексте сцены
  с `when.flags` допустимы `{trigger.past}`/`{trigger.when}` по первому флагу. Не ставить в неделе
  проценты и не давать прямых бонусов к броску — только через существующие флаги и ресурсы старта.

## Команды

```
npm run dev      # localhost:5179 (см. .claude/launch.json)
npm test         # 147 тестов: движок, контент, условия, M3, career, сезон, лига, цепочки, тиждень, критерии приёмки
npm run sim      # балансный прогон ботами; --random-conditions — со случайными условиями матча
npm run sim -- --season 12   # повторы эпизодов и текстов сетапа на дистанции сезона
npm run build    # dist/ — деплоится на GitHub Pages workflow'ом
```
