# Football Decision Prototype (v0)

Текстовый прототип футбольной RPG на украинском. Проверяет одну гипотезу: **интересно ли принимать
решения в отдельных футбольных эпизодах само по себе, без графики, анимации и симуляции поля.**

Если в текстовом виде скучно — концепт не спасут ни пиксель-арт, ни комикс-сцены.

## Запуск

```bash
npm install
npm run dev      # прототип на localhost
npm test         # юнит-тесты движка и проверки контента
npm run sim      # балансный прогон ботами, по умолчанию 1000 матчей на политику
npm run build    # статика в dist/
```

Выкладка — GitHub Pages: пуш в `main` запускает `.github/workflows/pages.yml` (тесты → сборка →
деплой). В репозитории один раз включить Settings → Pages → Source: GitHub Actions.

Экран `/stats` (ссылка есть с итогового экрана) показывает распределение выборов по эпизодам
из локальной телеметрии. Кнопка «Выгрузить логи» отдаёт весь лог решений одним JSON.

Матч воспроизводится по сиду: `?seed=12345` в адресе запустит тот же матч.

## Что где

```
src/engine/     чистая логика без React: бросок, контекст, машина состояний, все константы
src/content/    эпизоды, футболист и ростер — обычный JSON, править можно не глядя в код
src/ui/         экраны: лента, карточка эпизода, бросок, итог, /stats, debug
src/telemetry/  лог решений в localStorage
tools/simulate  балансный прогон
```

Пул — 23 эпизода на 10 слотов матча, чтобы второй матч не повторял первый. Фамилии партнёров
и соперников в текстах — плейсхолдеры (`{partner.dat}`, `{them.striker}`), формы падежей лежат
в `src/content/roster.json`: при смене команды в карьере эпизоды переписывать не придётся.

Весь баланс — в `src/engine/balance.ts`. После любой правки этого файла гоняем `npm run sim`.

## Чего в прототипе нет намеренно

Симуляции матча, спрайтов, комикс-сцен, карьеры, трансферов, сезонов, монетизации,
реролла, бэкенда, аккаунтов, звука и мобильной сборки. Любой из этих пунктов, добавленный
«раз уж всё равно делаем», ломает эксперимент.

## Текущие цифры баланса

Прогон на 2000 матчей на политику (`npm run sim -- 2000`):

| политика | результат | тренер | трибуны | голы ср. | badFail |
|---|---|---|---|---|---|
| always_safe | 6.23 | 7.04 | 5.43 | 0.00 | 4.9% |
| always_risky | 5.76 | 3.47 | 8.04 | 0.56 | 19.7% |
| greedy_personal | 5.93 | 3.55 | 8.30 | 0.87 | 19.2% |
| random | 6.28 | 5.06 | 7.50 | 0.41 | 14.0% |

Разрыв лучшей и худшей политики — 9.0% при пороге 15%, доля badFail — 14.5% при коридоре 8–15%.
Осторожная игра нравится тренеру и усыпляет трибуны, рискованная — наоборот; ни одна
из крайностей не выигрывает по сумме. Это и есть условие, при котором игра не превращается
в калькулятор.

Пороги исходов в `balance.ts` отличаются от первоначальной таблицы ТЗ: на исходных числах
доля badFail держалась около 35%, а `always_safe` выигрывал с отрывом 58%. Таблица подбиралась
прогоном, как и предполагал п. 11.

При расширении пула с 10 до 23 эпизодов баланс правился контентом, а не движком: в новых эпизодах
гол на `cost` заменён командным голом, часть «відчайдушно» понижена до «ризиковано», стоимость
дорогих опций подтянута к старым. Критерий по стамине смягчён с «во всех матчах до 70-й» до
«в половине до 70-й, во всех до 80-й»: с переменным пулом редкий сид из дешёвых эпизодов тянет
ноль до 76-й, а лечить это пассивным расходом — значит выбить badFail из коридора.

## Открытые вопросы — заполнить после теста на живых людях

Пять человек, по одному матчу минимум, логи собираются кнопкой на итоговом экране.

1. **В каких эпизодах распределение выборов оказалось однородным и почему.**
   Смотреть на `/stats`: любая опция больше 55% — повод присмотреться, больше 70% — эпизод
   переписывать, решение в нём мнимое.
   > _(заполнить)_

2. **Жалуются ли тестеры на рандом.**
   Если да — проблема, скорее всего, в подаче броска или в глубине провала, а не в математике.
   Проверять в таком порядке: видно ли модификаторы после броска, не слишком ли дорого
   стоит один `badFail`, и только потом лезть в `balance.ts`.
   > _(заполнить)_

3. **Хотят ли сыграть второй матч без просьбы.**
   > _(заполнить)_

4. **Что они рассказывают о матче своими словами.**
   Сравнивать с автопересказом на итоговом экране: совпадают ли моменты, которые запомнились
   человеку, с теми, которые прототип счёл ключевыми.
   > _(заполнить)_
