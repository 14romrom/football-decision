# Football Decision Prototype (v0)

Текстовый прототип футбольной RPG на украинском. Проверяет одну гипотезу: **интересно ли принимать
решения в отдельных футбольных эпизодах само по себе, без графики, анимации и симуляции поля.**

Если в текстовом виде скучно — концепт не спасут ни пиксель-арт, ни комикс-сцены.

## Запуск

```bash
npm install
npm run dev      # прототип на localhost
npm test         # юнит-тесты движка и проверки контента
npm run sim      # балансный прогон ботами, по умолчанию 1000 матчей на политику
npm run sim -- --season 20   # повторы эпизодов и сетапов на дистанции карьеры (два сезони)
npm run build    # статика в dist/
```

Выкладка — GitHub Pages: пуш в `main` запускает `.github/workflows/pages.yml` (тесты → сборка →
деплой). В репозитории один раз включить Settings → Pages → Source: GitHub Actions.

Экран `/stats` (ссылка есть с итогового экрана) показывает распределение выборов по эпизодам
из локальной телеметрии. Кнопка «Выгрузить логи» отдаёт весь лог решений одним JSON.

Матч воспроизводится по сиду: `?seed=12345` в адресе запустит тот же матч.

## Тема и экран решения (19.09)

Решение после макетов (артефакт «Екран рішення — макети», варианты А/Б/В → А2 + Г): матч верстается
как диалог в духе Disco Elysium. Тема — тёплая чёрная «бумага», плёночные кадры по краям (на широких
экранах), **Lora** для текста сцен (у Libre Baskerville нет кириллицы), **IBM Plex Mono** для
служебного, **Oswald** капителью для имён голосов; шрифты лежат локально в `public/fonts` (OFL),
чтобы работать офлайн в APK. Цвета голосов — как цвета навыков в DE. Токены в `:root` общие для всех
экранов; в новой геометрии пока только матч, остальные экраны — старая структура в новой палитре.

**А2 — экран решения** (`MatchScreen` + `Pitch` + `EpisodeCard`): сверху условное поле целиком, ми
атакуємо праворуч, точка гравця по семье/фазе эпизода (`Pitch.tsx`, эвристика до появления `zone`),
счёт и мини-шкалы тренера/трибун в углу поля. Под полем — стрічка подій як діалог: последние четыре
строки, старые гаснут и уходят под поле (`tape-shade`), остальное по кнопке «ще N подій». Сцена —
строка ленты с минутой, голоса говорят **до** вариантов («ЕГО — …», по одному разу на голос, слышно
только сильный; вставка «бачить» — тем же способом), варианты — нумерованный список с **одной
скобкой** `[форма ціль]` (+ `→ удар` для цепочки, чип «відкрив Бачення / з тижня»). Атрибута, бонуса
и цены сил на кнопке нет — самый короткий путь (решение пользователя). Внизу зона **«на кубик»**:
факторы состояния, которые движок добавит к любому варианту (`stateMods`: объединение
`computeContext` по вариантам без строки атрибута и «<голос> веде»; при разных значениях —
худшее), иконками (`ui/icons.tsx: modIcon` по подписи модификатора) и сили сегментами. Зона живёт
постоянно, чтобы игрок видел динамику: после провала появляется «після провалу −1».

**Г — кидок і результат** (`RollView`, вторая версия после разбора «дубли и сложно»): открывается
сам после выбора. Карточка строится вокруг кубиков — ключевой зоны азарта: выбранная строка красной
полосой, под ней два больших кубика с бегущими цифрами (барабан, 70 мс), первый останавливается
через 0,9 с, второй — через 1,8 с, между ними проявляется сумма; поправки прилетают чипами с
иконками по одной (первый чип — атрибут), итог справа тикает, формула остаётся (`13 +2 = 15 проти 14`
— решение пользователя), вердикт впечатывается штампом капителью, потом проявляется исход, реплика,
теги, «Граємо далі». Тап — пропустить анимацию; тап по строке чипов — полные подписи факторов.
Убраны: баннер атрибута, заголовок формы, таблица факторов, зона «на кубик» на этом экране (она
про следующее решение); подсказка «потрібно N+» под вторым кубиком отвергнута — лишнее число.
Позже: вибрация на остановке кубиков и вердикте (Haptics в Capacitor), звук барабана.

## Android

Сборка в сторы решена 19.09 как **веб + Capacitor** (React и CSS остаются; анимация матча и
мини-игры — Phaser в той же странице, когда дойдём). Локально JDK и Android SDK не нужны:
`.github/workflows/android.yml` собирает debug-APK на каждый пуш в `main` и кладёт по постоянной
ссылке — https://github.com/14romrom/football-decision/releases/download/android-latest/football-decision-debug.apk
(на телефоне: разрешить «невідомі джерела», открыть). `versionCode` = номер прогона, новая сборка
ставится поверх старой, карьера в localStorage сохраняется. `appId` — `ua.footballdecision.app`,
менять только до первой публикации. Папка `android/` — сгенерированный проект Capacitor, в git
без `assets/public` (это копия `dist`, делает `npx cap sync android`).

## Что где

```
src/engine/     чистая логика без React: бросок, контекст, машина состояний, все константы
src/content/    эпизоды, футболист и ростер — обычный JSON, править можно не глядя в код
src/ui/         экраны: лента, карточка эпизода, бросок, итог, /stats, debug
src/telemetry/  лог решений в localStorage
tools/simulate  балансный прогон
```

Перед матчем — брифинг с условиями (`src/engine/conditions.ts`): суперник из трёх клубов разной
силы, дом/выезд, погода, установка тренера, тонус из истории матчей на этом устройстве. Условия
генерируются по сиду, игрок их не выбирает; каждое обещание брифинга потом появляется строкой
модификатора после броска. Балансный прогон по умолчанию идёт на нейтральных условиях,
`npm run sim -- 600 --random-conditions` проверяет, что условия не ломают разрыв политик.

Пул — 123 плановых эпизода + 12 реактивных + 3 звена на 9 слотов матча, у каждого планового по 2–4 варианта сетапа
под ситуацию (счёт, минута, погода, поле, сила соперника, флаги) и, у самых частых, запасные безусловные (`when: {}`). Фамилии партнёров
и соперников в текстах — плейсхолдеры (`{partner.dat}`, `{them.striker}`), формы падежей лежат
в `src/content/roster.json`: при смене команды в карьере эпизоды переписывать не придётся.

Весь баланс — в `src/engine/balance.ts`. После любой правки этого файла гоняем `npm run sim`.

**Голос бачить** (17.09, `EpisodeOption.insight`): в 20 эпизодах сильный атрибут замечает деталь
сцены — «воротар за метр від лінії і переступає» — и открывает вариант, которого у другого билда нет.
Правил для игрока ноль: он видит строку и лишнюю кнопку. Стартовый Реєс видит Бачення (+4) и
Інстинкт (+3); Тіло и Спокій откроются прокачкой. Порог — `BALANCE.insightMinMod` (3),
выше слышимости голоса (2): слышно многих, видят сильные.

**Тиждень між матчами (17.09, вторая попытка).** Первая — «событие и три кнопки» — откачена как
поверхностная. Теперь неделя = шесть предложений, по одному на голос, из пула 57 дел на карьеру
(`content/activities.json`), взять до двух (с 19.09 — три дня по три, см. «Тиждень v3»). Дело — это голос, который берёшь на матч: зал делает Тіло
гучнішим (+1 к модификатору на матч) и забирает сили на старте; відео з аналітиком читает воротаря
до розминки; побачення з інстаграм-моделлю даёт кураж и трибуни, но сили и тренера — нет. Тренировки
копятся: четыре в один атрибут — +1 очко навсегда. Дела открываются по ходу карьеры (после первого
гола, по уровню, по результату, по флагам из матча: партнёр ображений → «поговорити»), `once` и
`cooldown` держат разнообразие — за сезон игрок видит ~34 разных. После разгрома тренер закрывает
город. Ирония в строке под названием — фишка игры. Прогон `npm run sim -- --weeks 150`: разрыв
политик недели по результату 2.6% — неделя меняет голоса и старт, а не исход матча.

**QA 17.09, вторая волна.** Уровни выключены (`BALANCE.growth.levels`) — рост только через тренировки
недели, три в один атрибут = +1 к модификатору. Его и Команда «бачать» по состоянию матча: серия
голоса (в том числе стартовая — от дела недели «Его гучніше») или кураж/доверие — и открывают свои
вставки (`show_the_sub`, `take_no_question`, `claim_the_chaos`, `trust_the_runner`, `call_the_overlap`);
ещё шесть атрибутных вставок в семьях press/partner/coach. Флаги недели попадают в сцены: «Вивчити
стандарти» → вариант «Розіграш із вівторка» на кутовому, «Розбір тактики» → «Як домовлялися на
розборі», «Провідати хворих» → «Той гол, який обіцяв»; сетапы этих эпизодов прямо ссылаются на тиждень.
На кнопке чип «відкрив Бачення» / «з тижня», после броска — строка, чей это был вариант. Реактив
`rx_ref_favor` — суддя на твоєму боці. Не больше двух травм за сезон (дальше — мікротравма). Регрессия
доверия 0.4 → 0.25, лояльность к тренеру — дела недели. Вердикт «лава» ужесточён (было 6% сезонов,
стало ~30% при случайной игре). Дела по месту в таблице (афіша дербі, ультрас біля бази, таблиця на
шафці) и с соперником по имени. `npm run qa -- 300` — прогон карьер на инварианты, чистый.

**Карточка и уровень (17.09).** Карточка — удостоверение по Disco Elysium: голоси первыми
(бачить / чутно / мовчить, Его против Команди по счётчику карьеры, девиз доминирующего голоса),
потом сезон, кар’єра, атрибуты. Очко уровня теперь +1 к модификатору броска (+4 к значению): раньше
+1 к значению три раза из четырёх не менял ничего. Экран уровня показывает, что очко сделает
с голосом («Тіло почне бачити»). Балансный прогон это не затрагивает — боты играют стартовым
Реєсом; пороги уровней удвоены (40 / 90 / 150 / 220 / 300…): 2-й уровень после второго матча, 5-й к концу
сезона — четыре очка за десять матчей, потолок +12 по одному атрибуту — три сезона.

**Реплика второго голоса** после броска (`flavor.json`): 311 строк, привязанных к семье сцены
(пенальті, один на один, штрафний, пресинг…) и голосу (ТРИБУНИ, ТРЕНЕР, ВОРОТАР, ПАРТНЕР,
СУПЕРНИК, СУДДЯ, ГОДИННИК, ТАБЛО, ТІЛО, КУРАЖ). Было 49 строк, к третьему матчу знакомые; теперь
пул взвешен по конкретности, виденные строки уступают свежим и через историю матчей — повторов за
12 матчей 3 из 108.

**Лента между эпизодами** (`feed.json`, `engine/feed.ts`): тот же механизм. Было 12 нейтральных строк
плюс по три на счёт в `match.ts` — на 16 показов за матч это 38% повторов внутри одного матча, 88% за
сезон, 23 уникальных текста; гол ленты — два шаблона на всё, перерва — одна строка. Теперь ~270 строк
по видам: `filler` (нейтральные, по фазе матча, счёту, усталости, погоде, дому/выезду, силе соперника,
его характеристикам `them_*`, куражу, жовтій, низкому доверию, нозі після стику), `goalUs`/`goalThem`
с манерой гола, `goalUsEcho`/`goalThemEcho` для гола из исхода эпизода (только автор и счёт — манеру
уже описал исход), `halftime` по счёту, `knock`, `kickoff` по полю. Замер 12 матчей с крутящимися
условиями: 179 строк ленты, повторов 0 внутри матча и 0 за сезон (тест держит порог 0 / 20%).

**Стрічка між матчами** (`posts.json`, `engine/posts.ts`, `PostsScreen` после таблицы; 18.09) — пародия
на твиттер, 9 постов по квоте: 3 про персонажа от болельщиков (по факту тура: гол, оценка, доверие,
дублер, партнёр, доминирующий голос), 2 про лигу (лидер проиграл, дно выиграло, следующий соперник по
его характеристике), 2 из большого футбола с реальными клубами (референс — присланные пользователем
шутки, переложены на украинский; реальных людей нет по правилу проекта; Россия — отдельный аккаунт),
1 пересечение миров («Барселона» не нашла клуб на карте), 1 мета (FM, Disco Elysium, EA). ~320 строк,
ответы под постами, лайки и время — декорация по rng. Память через `localStorage` (`recentPosts`):
тест — за 10 туров ни один пост дважды. **19.09:** +61 пост в «великий футбол» по списку пользователя —
абсурд с искажёнными, но узнаваемыми именами (Риштиану Коналду відібрав гол у хворого хлопчика, «Челсі»
підписав немовля на 50 років, Джанні Ніфантіно вручив премію миру Сталіну, чемпіонат світу на гольф-полі
біля вілли Трампа, золотий м’яч у Саудівській лізі, чищення килимів у трансляції МЛС, «соккер»), аккаунты
«Рабріціо Фомано» (абсурдные слухи, «Here we go»), «Футбольний філософ» (псевдофилософские размышления:
«Офсайд — це стан душі: ти вже там, а світ іще ні»), «ФІФА Leaks». Квота «світу» в стрічці 2 → 3. **Доля игрового мира растёт с сезоном** (19.09): в первом сезоне
игрок ещё не знает ни Кнаппа, ни «Терра-Нови» — квота `postQuota(1)`: про нас 3 (self 2, league 1),
общих 7 (world 5, meta 2); со второго сезона — прежняя (self 3, league 2, cross 1, world 3, meta 1).
Новые пародийные аккаунты в «світі»: «Прогнози від Капітана» (беттинг, прогноз всегда мимо), «Фентезі-менеджер
року» (девять дней не выходил из дома), «Тактичний експерт» (тактика по хайлайтам), «Спортфарм™» (реклама
допинга: «100% натуральний, 0% дозволений»), «дівчина футболіста (в процесі)». +50 строк.

**Стрічка «живая» (19.09, решение пользователя — пункты «ответ как решение» и «форма», тексты
менее литературные).** (1) Фанатские посты про нас переписаны как пишут: с маленькой, без тире, «шо»,
«капець», КАПСЛОК после поражения, ))), один хештег; издания и пародийные аккаунты — по-прежнему
чисто, это их характер. (2) Виды постов (`PostRule.kind`): `poll` — опрос с абсурдными вариантами,
проценты раздаёт rng, один всегда побеждает неприлично («Хто винен? тренер / суддя / погода / Реєс»);
`deleted` — «Цей твіт видалено» от клуба, а фанат в ответе цитирует скрин; `promo` — реклама с
пометкой (Спортфарм™); `live` — лайв-твиты с минутой матча вместо «N год», уходят в низ ленты.
(3) **Ответ игрока — решение без кубика:** у поста могут быть `replyOptions` (три реплики, у каждой
реакция автора и `effect` как у дела недели), в одной стрічці — не больше одного такого; если
подходящий есть в пуле, он подмешивается с вероятностью `REPLY_CHANCE` 0.5 (≈6 из 10 туров). Ответ
уходит через `applyWeek` (теперь дополняет `nextMatch`, а не затирает — иначе тиждень стирал бы
последствия) и виден на брифинге в «Наслідках». Промпты: модель после побачення, фан дублера при
низком доверии, тато з трибуни после поражения, «тактичний експерт», абонемент без ударов. Ответы
дают трибуны/тренер/кураж и флаги (`viral_story` → провокация в матче, `week_promise` → «той гол,
який обіцяв»). Проверено в браузере: ответ «експерту» → «спокій ↓, трибуни ↑» → на брифинге
«Посперечався з «експертом» у стрічці». Попутно: экран «Новий рівень» больше не показывается при
выключенных уровнях (он обещал очко, которого нет).

**Тиждень v3: діло → ісход → слід (19.09, решение пользователя — механика голосов 1+2+4).**
Неделя стала тремя днями по три предложения, одно дело в день. Дело больше не «карточка с
эффектом»: у каждого из 66 дел 1–3 исхода (`Activity.outcomes`, всего 131), и какой выпадет — игрок
узнаёт вечером: вечеря с командой — поговорили с партнёром до закрытия (`partner_trusts`) /
посварились на десерте (`partner_annoyed` + сцена) / просто хорошо; побачення — сторіз с базой
(тренер −, сцена) / она разбирается в футболе лучше журналистов (Спокій гучніший) / не
пришла. Три способа, которыми голоса влияют на исход (`resolveOutcome`): (1) **доминантный голос
карьеры** (`dominantCareerVoice`, ≥ 6 решений и без ничьей) удваивает вес «своего» исхода — игрок,
живущий Его, чаще ссорится на вечере и чаще всплывает в сторіз; (2) **проверка атрибута**
(`check: {attr, min}` по модификатору) — сильный Спокій открывает «зал с головой» вместо
перебора, слабая почти закрывает; (4) **голос бачить между матчами** (`weekVoiceSees`: атрибутные — как
в матче, Его — трибуны ≥ 7 или доминантный, Команда — доверие ≥ 70) открывает в сцене-продолжении
четвёртый вариант с подсказкой «Бачення: він не хоче відповіді, він хоче заголовок». Ситуация тоже
двигает веса (`boost` = условие `when`): после поражения безсоння втрое чаще. Исход считается заранее
тем же rng, что и предложения — перезагрузка не даёт перебросить вечер; кубика на экране нет.
Десять сцен-продолжений (`content/weekscenes.json`, одна на неделю): сварка с партнёром, сторіз
модели, звонок тренера в понедельник, видео дублера, ультрас у ворот, вопрос про судью, обещание
хлопчику, карточный долг, тайна аналитика, звонок агента. **Обида голосов** (`neglectPenalties`): голос,
который предлагал три недели подряд и не был взят, замовкає на следующий матч (`quieter`). Между днями
— один мировой пост зі стрічки (квота `world: 2`). Всё применяется разом в конце недели
(`finishWeek` → `applyWeek`), в `weekLog` пишутся исходы и сцена. Правило контента: каждый исход обязан
оставить след (тест: эффект кроме `note`), ⅔ дел — с развилкой. Прогон `--weeks 150`: разрыв
политик недели 4.2%. Проверено в браузере: закрытый город → три дня заполнены базовыми голосами;
«Прес-конференція» → пауза → сцена с вопросом про судью → вариант от Бачення → «заголовок вийшов на
твою користь».

**Реакция на конкретный момент (19.09).** Матч отдаёт в сезон два момента (`match.ts:pickMoments`):
худший — катастрофа → решение, после которого пропустили → провал; лучший — гол → ассист → чистый
«вирішити». В `posts.json` условие `moment: worst | best` и плейсхолдеры `{moment.minute}`, `{moment.ord}`
(«62-га»), `{moment.acc}` («62-гу»), `{moment.past}`, `{moment.recap}` — родовий и місцевий пишутся
прямо («{moment.minute}-ї хвилини», «на {moment.minute}-й», одинаково для всех чисел). Болельщик цитирует
ровно то, что игрок выбрал: «на 71-й Реєс виніс головою з лінії воріт. я кричав так шо сусід зверху
постукав». Если момент был, один пост о нём гарантирован (поражение — худший, победа — лучший), включая
опрос («це було: рішення / помилка / план тренера / я не дивився»), лайв с той же минутой и пост
с ответом (пояснити / визнати / огризнутись). 18 правил, ~45 строк.


## Чего в прототипе нет намеренно

Симуляции матча, спрайтов, комикс-сцен, карьеры, трансферов, сезонов, монетизации,
реролла, бэкенда, аккаунтов, звука и мобильной сборки. Любой из этих пунктов, добавленный
«раз уж всё равно делаем», ломает эксперимент.

**M27.2 — ланцюжки почали спрацьовувати (26.09.2026).** Лог кар'єри: `fin_shot` зіграв **один раз за 20 матчів**,

`npx tsx tools/chain-rate.ts 400`: ланцюжок був у **17% матчів** (0.18 на матч). Причина не в лімітах — вони не
вибиралися жодного разу (`maxChainsPerMatch` 2, `maxLinksPerSlot` 2, обидва 0%), і не в тому, що ланка вже грала.
Причина: **вхід висів майже тільки на `clean` (47 із 68 ісходів), а `clean` на цих варіантах випадає лише в 17%** —
ланцюжки причеплені до найважчих варіантів (ризик, висока складність), тоді як `cost` на них — 38%. Тобто нагорода
стояла за найвужчим горлечком, а лог показав, що гравець грає обережно (55% рішень «упевнено»). Зроблено три входи
**без нових механік, тільки розширенням наявного задуму**: (1) «фол на межі штрафного → `ep_free_kick_close`» — патерн
у грі вже був у 8 місцях, тепер він є в усіх ісходах, чий текст і так закінчується штрафним біля штрафного (+8);
(2) «заробив кутовий → подаєш його сам» (`ep_corner_delivery`) на ісходах, де кутовий заробив саме Реєс (+6);
(3) організаційні «упевнено»-варіанти — правило проєкту давно каже нагороджувати їх ланцюжком, а не голом, але
покриття було неповним (+8, `ep_decoy_run`, `ep_switch_play`, `ep_counter_without_ball`, `ep_half_space_pocket`,
`ep_second_wave_run`, `ep_far_post_cross`, `ep_cut_in_shot`, `ep_two_v_one_lead`). Стало: ісходів із ланцюжком 68 → 90,
варіантів 50 → 65, ланцюжок у **32.5% матчів** (0.38 на матч), і тепер він частіше веде в кутовий і штрафний, ніж у
`fin_shot`, — тобто в рішення, а не лише в удар. Аудит зловив побічний ефект: ланцюжок у `ep_wing_overlap/release_overlap`
підсилив і без того найкращий варіант (відрив EV 1.52) — приз перенесено в `ep_two_v_one_lead`, де лідера немає.
`sim 2000`: розрив політик 7.3% → **5.8%**, badFail 9.1%, матчів з голом 31%.

**Мікротравма** (`knock`, `BALANCE.knock`): событие ленты — стик між епізодами, после которого нога

реактивный `rx_knock`: грати далі (ризик порвати м’яз → `injured` на следующий матч), берегти ногу
(тренер бачить, дублер встає), лікар на паузі. Полных травм из-за неё ≈1–4% матчей.

  в каждом был осязаемый плюс.
- Перерыв возвращает 8 сил; варианты на швидкість/корпус стоят на 4 дороже (`optionCost`).
- Слой реплик по ситуации (`flavor.json`): короткая ироничная фраза после исхода, зависящая
  от счёта, минуты, усталости, серии, карточки и доверия тренера.
- Игра стала щедрее: у бота, бьющего из каждого эпизода, 1.2 гола за матч и хвост до 4 —
  критерий по хвосту поднят с 3 до 4. Случайная политика держится на 0.6 гола и 38% матчей с голом.
  Критерий по стамине: медиана до 70-й, 90-й перцентиль до 80-й (редкий сид с пенальти и перерывом
  тянет ноль до 82-й).

**Второй раунд (по логам двух матчей):**

- Скилл виден на фоне кубика: модификатор атрибута считается от 45 шагом 4 (`ATTR_MOD`), стартовый
  коридор 45..65 даёт 0..+5 и никогда не минус; в строке броска показывается значение — «пас (62) +4».

  плюс «ноги стали −4», после которой любой риск невозможен.
- 9 эпизодов вместо 10 и квота — минимум 3 оборонительных за матч (`minDefense`, слоты под них
  выбираются заранее). Пул 27: добавлены четыре защитных эпизода (последний защитник, блок удара,
  опека плеймейкера, розыгрыш их углового накоротке).
- Память между матчами: эпизоды двух последних матчей получают вес 0.02 (`recentWeight`). Второй
  матч повторяет первый на ~4%, третий — первые два на ~32% (без памяти ~33% и ~55%); дальше снижает
  только рост пула.
- Условия матча проверены изолированно (600 матчей на условие): соперник, усталость и установка
  тренера работали, погода и форма были косметикой. Дождь и ветер теперь −2, жара ×1.5 к расходу,
  форма — стартовый кураж ±1, который живёт дальше как обычный momentum. Скрипт замера —
  в комментарии к `BALANCE.conditions`.
- Критерий по стамине под 9 эпизодов: медиана до 75-й (до двух последних слотов), p90 до 80-й.

**M3 — голоси і наслідки (Disco Elysium):**

продукте; «Паненка» — генерализованный футбольный термин, отдельный случай). После расширения:

Новый контент в среднем дешевле по силам (макс. по эпизоду 7.7 против 9.9 у исходных 27) — это

**Сезон без повторов — все три пути сразу (16.09.2026).** Почему пул плохо масштабируется: сезон —
10–12 матчей × 9 слотов ≈ 100 эпизодов, а память была плоской на два матча, с третьего весь пул снова
равновероятен; каждый эпизод — ~15 текстов исходов под десятком инвариантов и балансным прогоном; повторы
определяет самая узкая подкатегория (оборона 15 эпизодов на 3 слота квоты, стандарты 4), а не сумма;
единица повтора — текст сетапа, который не знал ни счёта, ни погоды. Замер теперь воспроизводим:
`npm run sim -- --season 12` (200 сезонов, случайная политика). Что сделано:

- **Память на сезон** (`BALANCE.match.memory`): два последних матча — почти запрет (0.002), дальше вес
  растёт от 0.02 до 1 по квадрату на горизонте 12 матчей. Выборка с возвращением стала «колодой» без
  роста пула: на старом пуле 53 повторы к 4-му матчу 42% → 18%, к 6-му 66% → 44%, повторы из двух
  последних матчей остались 3–5%. Одна кривая без жёсткой ступени поднимала их до 15% — веса возраста
  1 и 3 становились сравнимы, поэтому ступень.
- **Вариации сетапа по ситуации** (`Episode.setups`, тот же механизм `when`, что у `flavor.json`,
  плюс `venue`/`weather`/`strength`/`flags`; побеждает самое конкретное правило). Опции и исходы у эпизода
  одни, сцена читается по-разному: пенальти на 88-й при нічиїй и при 0:1 — разные тексты. 89 вариантов
  на 44 эпизодах. Это и есть «композиция» в дешёвом виде: слой ситуации отделён от слоя решения; общий
  набор опций на разные сетапы не делал намеренно — тексты исходов ссылаются на детали сцены.
- **Эпизоды по счёту** (`requires.score`): затяжка времени при преимуществе, погоня при отставании.
  Проверяются в момент показа, как `notFlags`; если подменить в плане нечем — берётся свежий эпизод
  вне плана (раньше закрытый флагом эпизод в таком случае игрался как есть).
- **Пул 48+5 → 68+7** по списку из 78 футбольных ситуаций: из них уже покрывали пул ~30 (стеночка,
  провокация игрока на жёлтой, перекидывание вратаря, блок удара, тактический фол, быстрый штрафной…);
  20 стали новыми плановыми эпизодами (забегание/ложное забегание/офсайдная грань, пас вразрез
  низом/верхом/в зону, третий игрок, пропуск мяча, выдернуть защитника, смена фланга, решение на лицевой
  (назад под удар / силовой прострел / дальняя / гострий кут), обманный замах, пас против высокой линии,
  офсайдная ловушка, прессинг-ловушка, вынос с линии с рукой и без, кутовий-подача и кутовий-бегун,
  ближний штрафной (через стенку / под стенкой / розыгрыш), затяжка времени, погоня, после отбора
  (контратака / успокоить / перевод), разговор с судьёй, провокация); пас внешней стороной — четвёртая
  опция `ep_disguised_pass`. Не переносил механики, которых нет: серия пенальти, реальное удаление
  внутри матча (`sent_off` по-прежнему действует со следующего матча), отдельная шкала доверия судьи —
  вместо неё флаги.
- **Реактивные шаблоны и сезонные флаги.** Два новых: защитник прочитал повторяющийся проход по бровке
  (`pattern_wide` ставят `ep_wing_one_on_one`/`ep_flank_reception`) и судья запомнил симуляцию/спор
  (`ref_annoyed`; `ref_sympathetic` — обратный). Флаги о людях — долг/обида партнёра и доверенный фланг
  тренера — переживают финальный свисток (`career.carriedFlags`, `CARRIED_FLAGS`): реактивный эпизод
  следующего матча говорит «ще минулого матчу ти {trigger.past}» через `{trigger.when}`/`{trigger.When}`.
  Злой защитник и жёлтая — про этот матч, их не несём. Реактивные шаблоны тоже помнят сезон: в логе
  плейтеста `rx_partner_return` всплывал три матча подряд, потому что `pickReactive` смотрел только на
  флаг; теперь шаблон из прошлого матча всплывает с вероятностью своего веса памяти (флаг остаётся).

**Заход A — сезон и люди (17.09.2026).** Тестеры: «игра на 15 минут». Повторы — половина причины,
вторая — между матчами нечего терять. Сделано:

- **Сезон** (`engine/season.ts`, M5-лайт): лига из 6 клубов — мы и пять соперников из шести в ростере
  (состав лиги перемешивается по сиду, второй сезон не повторяет первый), 10 туров по кругу, соперник
  и поле матча — из расписания, чужие матчи — Пуассон по силе клубов (свой rng по сиду сезона и туру).
  После каждого матча — таблица, место, «до кінця N турів», бомбардиры своих; в конце — вердикт по месту
  и доверию тренера: дзвонить агент / продовження / розмова в кабінеті. Хранилище — `season-storage.ts`.
- **Персонаж по имени**: `self` в ростере с падежами; свой гол в ленте — «Реєс забиває — гол!»,
  протокол на итоговом экране («Кнапп 21′, Мораес 72′ — їхній ветеран 80′»), строка «Даніель Реєс ·
  тренер 6.6 · трибуни 8.2», голы/передачи за сезон и бомбардиры команды.
- **Своя команда — 12 ролей** (было 5): + `cb2`, `rb`, `lb`, `winger`, `sub` (дублер по имени),
  `coach` (тренер по имени), `self`. Дублер — угроза с флагом `sub_threat`, переживающим свисток;
  тренер по имени зовёт к брівці; новые строки ленты между эпизодами с новыми именами.
- **Соперники без фамилий** — характеристики с падежами («їхній ветеран», «молодий вінгер», «різкий
  опорник», «місцевий улюбленець»…), с большой буквы в начале предложения (`names.ts`). Каждая
  характеристика — флаг `them_<trait>` на матч (правило-модификатор в `flags.json` и `when.flags` для
  сетапов): дриблер −1 позиції в обороні, ветеран не купується на фінти, молодий провалюється, різкий
  б’є по ногах, капітан говорить із суддею. Рода/числа согласованы: только мужские, и такие, у которых
  родительный совпадает с винительным (контент подставляет `.gen` как винительный).
- **Голоса имеют вес** (`BALANCE.voice`): слышимый голос атрибута даёт +1 на своём варианте («Бачення
  веде»); три раза подряд слушал Его — командные варианты на −1 («Его заглушило команду»), Команду —
  личные на −1. Его и Команда бонуса к броску не дают: они спорят, а не помогают.
- Пересказ: у 60 исходов нового контента `recap` повторял `past` («навісив — і навісив»), переписаны
  на последствия; ловится скриптом по первым двум словам.

**Заход B — связи между эпизодами (17.09.2026).** Тестеры: «пенальті — незрозуміло, як б’єш»; общая
просьба — сценарная вариативность и привязка эпизодов друг к другу.

- **Цепочки** (`apply.followUp`): исход сразу ведёт в следующее решение в том же слоте, без ленты —
  заробив пенальті → сам б’єш, обіграв → удар, фол біля штрафного → штрафний. Лимиты
  `BALANCE.match.chain`: ≤2 звена в слоте, ≤2 цепочки за матч; звено уже сыгранное в матче не
  повторяется, а плановый эпизод, который цепочка забрала раньше своего слота, считается закрытым и
  подменяется. Если цепочка не может сработать, исход достраивается `followUpElse` («суддя свистить
  пенальті» без твоего удара = б’є {striker}). Тест проверяет, что у каждого `followUp` есть цель и
  `followUpElse`. В тексте звена работает `{trigger.past}` предыдущего решения.
- **Модуль завершения** `fin_shot` (эпизод-звено, `followUpOnly`): одна сцена удара, куда ведут восемь
  исходов из разных ситуаций (фінт усередину, зміщення в центр, розворот між лініями, третій гравець,
  витягнутий захисник, пропуск м’яча, прискорення…). Четыре манеры: закрутити в дальній, зовнішньою
  стороною не міняючи корпус, на силу, низом між ніг. «На силу» с сейвом ведёт дальше в добивание
  (`ep_rebound_follow_up`) — второе звено.
- **Пенальти-семья.** `ep_penalty_won` (плановый: хто б’є — взяти / віддати {striker.dat} / забрати
  м’яч і потягнути) → `fin_penalty_wait` (воротар тягне час: дивитися в очі / поправити м’яч / судді)
  → `fin_penalty` (манери: у кут на силу, дочекатися руху, під поперечину, паненка). Старый
  `ep_penalty_taker` («взяти/віддати/паненка») убран — его роль разложена по цепочке.
- **Скрытое чтение воротаря.** У каждого клуба воротар со звичкою (`roster.json → keeper.trait`:
  падає рано / стоїть до останнього / тримається ближньої / виходить рано) — флаг `keeper_<trait>` на
  матч. Правила в `flags.json` бьют по **манере** (`FlagRule.options`), а не по атрибуту: «падає рано»
  +2 паненке и «дочекатися руху», −2 им же, если «стоїть до останнього». Строка модификатора после
  броска — и есть чтение: первый удар ставит `keeper_read`, дальше сетапы удара/пенальти говорят, что
  ты знаешь («він падає рано — треба лише дати йому впасти»), а паненка появляется как вариант
  (`EpisodeOption.requires.flags`) только у того, кто прочитал воротаря, который падает рано. До
  первого удара воротаря читают бачення поля от +5 (стартовый Реєс с +4 — нет, после роста — да) и
  аналитик на брифинге с шансом. `keeper_read` переживает свисток только до матча с тем же клубом
  (`OPPONENT_BOUND_FLAGS`).
- **Семьи** (`Episode.family`, 14 семей): память сезона давит семью слабее id
  (`familyFloor` 0.3) — пенальті вчора не запрещает пенальті сегодня, но делает его реже.
- Тренування между матчами убрано (см. M2).
- Баг из плейтеста: `{cb2.gen}` в ленте — регулярка плейсхолдеров не знала цифр; тест теперь гоняет
  40 матчей и ищет `{` в каждой строке ленты.

Результат на пуле 75 с памятью: повторы id к 4-му матчу 6%, к 6-му 35%, к 12-му 85% (108 слотов на
68 плановых — потолок арифметики); из двух последних матчей — 2–4%; повторы **текста сетапа** — 2% / 14% /
53%. Дальше сезон удлиняет только контент, но теперь каждый новый эпизод стоит дешевле: вариант сетапа —
две строки, а не 15 исходов. Балансные критерии держались контентом: физически дорогие опции новых эпизодов
(ривок, обводка, контратака) стоят 9–11 сил, иначе медиана критерия по стамине уезжала на 80-ю.

**M2 — рост (16.09.2026):**

- **Опыт и уровни.** XP за матч = база(8) + округлённые оценки тренера/трибун + бонус(3) за чёткий
  характер (доминирующий голос, тот же порог, что и в пересказе). Таблица уровней возрастающая
  (`LEVEL_THRESHOLDS` в career.ts) — первые уровни быстро, дальше реже. На уровне игрок сам выбирает
  +1 в один атрибут (`LevelUpScreen`) — рост должен ощущаться как решение, а не строчка в логе.
- ~~Тренування между матчами~~ — убрано 17.09 по плейтесту: бросок после матча не ощущался как
  рост (тестеры: «не засчитывается»), а рост уже есть через уровень с выбором атрибута.
- **Перенос между матчами.** Доверие тренера продолжается с регрессией к среднему
  (`nextMatchCoachTrust`) — один провальный матч не портит карьеру навсегда, один удачный не решает
  её навсегда. Жёлтые копятся, на третьей — тренер начинает следующий матч настороже (−15 доверия);
  красная карточка бьёт сильнее (−25). Травма — −20 к стартовым силам следующего матча. Всё это не
  скрыто: причина видна на брифинге строкой «Наслідки».
- Персонаж для матча — `effectivePlayer()`: база + накопленные очки прокачки, зажато 1..99;
  `attrMod()` всё равно ограничивает модификатор потолком +12, так что раскачать бросок до абсурда
  нельзя даже на высоком уровне.
- Хранилище — `telemetry/career-storage.ts`, отдельный ключ localStorage, сливается с дефолтом
  при чтении (новое поле Career не сломает старое сохранение).
- 14 новых тестов на career.ts (91 всего).

**Баг из плейтеста (16.09.2026) — автор гола в сценарии и в хронологии расходились:**
исход называл конкретного партнёра («{partner} забив з твоєї передачі»), а лента матча объявляла
гол случайным именем из `roster.scorers` — pushGoal не знал, кого уже назвал текст. Добавлено
`apply.scorer` — ключ игрока, который должен звучать в объявлении; проставлен автоматически по
плейсхолдеру в тексте для всех 22 assist, 17 teamGoal и 15 именованных concede. Заодно нашёлся
второй случай той же болезни: на критическом успехе экран броска показывал обычный «чисто», а в
ленту уходил другой, крит-текст — RollView и applyChoice считали исход независимо. Вынесено в общую
`pickOutcome()`, используется в обоих местах.

**Чёткий результат «в моменте»** — теги по факту произошедшего (`resultBadges()` в resolve.ts,
чистая функция от `apply`), отдельно от яруса броска (тот про качество попытки, не про итог):
⚽ Гол, 🅰️ Гольова передача, 🥅 Пропущений гол, 🎯 Точний пас, 💪 Виграна дуель, ❌ Втрата м'яча,
🚩 Кутовий, ⚠️ Ризик контратаки, 🟨 Фол/картка, 🤕 Пошкодження. Показываются на экране броска и
рядом с событием в ленте — один источник (TimelineEvent.badges), не дублируется в двух местах.

**M3, продолжение — голос имеет вес, тренер и трибуни получили механику:**

- **Голос, который слушают, становится громче.** `state.voices` копит счётчик по каждому голосу
  и серию подряд (`streak`). Послушав Его два раза подряд, он перекрикивает даже серию провалов
  (обычно затихает при `momentum < 0`) — а Команда от этого замолкает, даже если у неё есть право
  голоса по цели варианта. Это первый слой «выбор имеет вес»; полный перенос между матчами и
  черта из накопленного профиля — в M2/M4.
- В пересказе — какой голос звучал громче всех, если хотя бы 3 раза: «Цього матчу найгучніше
  звучав Его — ти слухав його 6 разів.» Строка дописана к итоговой (тест на 4–6 строк не задет).
- **Тренер — симметрично.** Раньше доверие только карало: `coachTrust < 30` сдвигало риск на шаг
  хуже. Теперь `coachTrust ≥ 80` даёт симметричный бонус — масштаб эффекта растёт на шаг
  (`effShift`). Тренер, которому доверяют, даёт больше свободы, а не только меньше наказывает.
- **Трибуни — не разовый бонус, а затяжной дрейф.** Заряджені трибуни (`fanHype ≥ 70`) постепенно
  поднимают `composureNow`, мовчазні або ворожі (`fanHype < 20`) — постоянно давят все 90 минут.
  Работает через уже существующие точки входа: пороговый мод «спокійний у кінцівці» после 80-й
  и слышимость голоса «Спокій» — трибуни не заводят третий механизм, а двигают то,
  что уже что-то значит.
